# Параметры промптов

Запросы к LLM GigaChat имеют следующие параметры

*   Температура равна по умолчанию 0.2.
    Более высокие значения температуры следует использовать с осторожностью,
    так как они могут снизить стабильность оценки релевантности заказа навыкам
    исполнителя.

*   Для ограничения длины ответа могут использоваться два параметра, существенно
    отличающихся по своим функциям, поэтому важно различать их.
    Параметр MAX_TOKENS, определяемый в начале файла `generate_response.py`,
    задает аргумент max_tokens передаваемый через API модели. Это жесткое
    ограничение длины ответа, которое модель не может нарушить. Это ограничение,
    задается в токенах модели, средняя длина которых составляет около 3-3.5 символов.
    Параметр MAX_OUTPUT_CHARS, также определяемый в начале файла `generate_response.py`,
    задает максимальную длину ответа модели в символах, которую модель получает
    с системным промптом и стремится сгенерировать ответ, не превосходящий этой длины.

    Хорошая практика использования этих параметров - использование MAX_OUTPUT_CHARS
    для установки предпочтительной длины ответа и задание большего значения для
    MAX_TOKENS, используемого для того, чтобы ограничить длину ответа модели в
    случае ее сбоя, который приведет к игнорированию MAX_OUTPUT_CHARS. Хорошим
    значением MAX_TOKENS для этого является половина значения MAX_OUTPUT_CHARS
    или несколько больше, чтобы фактически длина ответа в символах не превысила
    полтора-два значения MAX_OUTPUT_CHARS.

    При этом использование меньшего значения MAX_TOKENS, чем половина MAX_OUTPUT_CHARS,
    нежелательно, так как может привести к тексту ответа, который оборвется на полуслове.
    Использование же значительно большего значения MAX_TOKENS может привести к лишним
    расходам в случае, если в результате сбоя в работе LLM параметр MAX_OUTPUT_CHARS
    будет проигнорирован и модель сгенерирует очень длинный (и скорее всего не
    подходящий для целей использования ассистента) текст.

*   Следует использовать модель GigaChat-2-Pro или GigaChat-2-Max.
    Используемая модель определяется значением MODEL в файле `generate_response.py`.
    Допустимое значение GigaChat-2-Max дает более качественный ответ чем
    GigaChat-2-Pro, но стоит дороже на 30% (согласно тарифам опубликованным
    на момент 26 ноября 2026). Третье теоретически возможное значение GigaChat-2
    не рекомендуется к использованию, так как часто приводит к необоснованной
    оценке соответствия заказа навыкам исполнителя и генерации бессмысленного
    отклика в этом случае.

*   Параметр MIN_RELEVANCE определяет минимальное значение степени соответствия
    заказа навыкам испонителя. Если степень соответствия заказа навыкам выше
    этой, то будет сгенерирован отклик на заказ, а если ниже, то не будет.
    Значение по умолчанию равно 50%, теоретически возможный диапазон значений
    от 0 до 100, практически рекомендуемый от 30 до 70. Слишком маленькое значение
    приведет к необоснованным тратам на генерацию откликов на нерелевантные
